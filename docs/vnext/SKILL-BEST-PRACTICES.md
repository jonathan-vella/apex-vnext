# Managed Skill Best-Practice Review

> CP-18 #384 and CP-21 #401: source review and deterministic checks, not live-client or model-quality qualification.

## Source and Scope

- Official guidance: [Anthropic Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices),
  retrieved on 2026-10-20. The official Markdown response had SHA-256
  `727f3fa1168eb1c33ce6a3cbfc94a02ef1dfd647388f6ca9daf7cb6294762f42`. This is a retrieved-content fingerprint, not
  an upstream Git commit or a permanent promise about that mutable URL.
- Approved port source: `jonathan-vella/apex@c209d8bb765681aa21dce5d3cd2a3b080dad8d5e`, following the
  [maintainer-agreed map](https://github.com/jonathan-vella/apex-vnext/issues/384#issuecomment-6065331877).
- Runtime baseline: merged `cd6a3a79b2f9c6c4bb0e10bb7a7cfe75994c21fc` after #496 and #497. The published
  `0.11.0-next.5` client candidate is not replaced or requalified by this review.
- Scope: all managed skill entrypoints, the core workflow skill pass, four approved domain additions, their source
  coverage, progressive disclosure, metadata, routing/scenario declarations and plugin ownership. Repository-maintainer
  skills are not being re-ported or globally rewritten.

The review separates manual guidance assessment from machine-checkable structure. A catalog, keyword fixture or
passing lint cannot establish whether a particular model actually discovers a skill, follows it correctly, judges
an architecture well, or completes a real client workflow. Those remain candidate-bound CP-20 #386 observations.

Checkable evidence is implemented in the [skill validator](../../tools/scripts/validate-skills.mjs) and its
[boundary tests](../../tools/tests/validate-skills.test.mjs). Delivery and discovery declarations are recorded in the
[plugin manifest](../../customizations/manifest.json),
[scenario corpus](../../tools/registry/skill-catalog-review-scenarios.v1.json) and
[catalog regression tests](../../tools/tests/validate-skill-catalog-review-scenarios.test.mjs).
Each skill linked below identifies its selected references and, for the four additions, its per-file upstream coverage.

## Evaluation and Evidence Boundary

The maintained skill-catalog scenario fixture records intended inputs, selected skill or explicit near-miss, expected
behavior/evidence and `not-run` client/live states. New domain scenarios include:

- AKS design versus VM/incident topics, and refusal of direct cluster changes/credential retrieval.
- Reliability reasoning versus claimed restore/compliance evidence, and refusal of direct failover/drill execution.
- Functions/Redis lifecycle assessment versus actual migration/application execution.
- Supported Architecture/WAF/cost figures versus imported Python execution or an unregistered ERD/wireframe.

Core skill examples exercise status-only, missing-project, intake-only, stale/request ownership, review disposition,
worker completion and human-gate stops. Tests verify the declarations and source/packaging bindings; they do not
execute a live Copilot session or prove that keyword matching measures reasoning quality.

Before marking behavioral acceptance, the human-run CP-20 candidate must include these exact guidance bytes, models,
client versions, tool grants and host observations. Record actual discovery/navigation and positive/negative outcomes.
Do not run unattended model comparisons or change models to create a passing receipt.

## Delivery and Review

The four new skills are Agent Plugin-owned, not copied to consumer workspaces. Their coverage records and the
[upstream ledger](../../tools/registry/skill-upstream-pins.v1.json) record every pinned source-file disposition,
including executable helpers deliberately excluded because existing runtime ownership replaces them.

The [guidance registry](../../tools/registry/guidance-delivery.v1.json), managed manifest, generated catalog, focused
tests and plugin package must agree. No skill-baseline suppression, agent invocation edge, cloud grant, renderer or
new independent runtime authority is introduced. Maintainer content review, live client qualification and any
publication remain distinct decisions.
